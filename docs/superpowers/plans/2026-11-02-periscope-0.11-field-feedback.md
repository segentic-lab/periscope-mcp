# Periscope 0.11.0 "Field feedback" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship one release (0.11.0) that closes all sixteen asks from the two field reports: honest click/fill results, fresh-deploy navigation, device + consent-aware sessions, PWA/frames/download inspection, network and Lighthouse summaries, tiled screenshots, and staging-vs-live page comparison.

**Architecture:** Every feature reuses the existing machinery (step executor, session buffers, `attach_observation`, `compare_screenshots`, `resilient_goto`). New behaviour that is pure logic lives in small new modules (`pagechange.py`, `devices.py`, `consent.py`, `lighthouse_summary.py`, `handlers/pwa.py`, `handlers/compare.py`) so it is unit-testable without a browser; handlers stay thin. Session results gain a `nav_generation` counter injected at the single dispatch chokepoint in `server.py`.

**Tech Stack:** Python 3.11+, Playwright (async), httpx, Pillow, pytest (`tests/` unit, `tests/e2e/` real Chromium against `tests/e2e/fixtures/`).

**Spec:** `docs/roadmap-0.11-field-feedback.md` (sections 1 and 3; owner decisions in section 4 resolved: hint by default + `strategy="auto"` opt-in; device sessions in a private context seeded with the project's storage state; network sizes from resource timing with `content-length` fallback; one release).

## Global Constraints

- Branch: `beta/0.11-field-feedback` off `main`; commit per task; never push without the user.
- Every tool addition follows CLAUDE.md: `Tool(...)` in `tool_schemas.py`, `@tool` handler, coercion whitelist, `tests/test_registry.py` green.
- Results are always `{"success": false, "error": ...}` on failure; every error text names the fix.
- URL patterns are plain substrings. No Playwright selector syntax exposed in tool inputs.
- Unit suite: `venv/bin/python3 -m pytest tests/ --ignore=tests/e2e -q`. E2E: `CHROMIUM_PATH=/snap/chromium/current/usr/lib/chromium-browser/chrome PERISCOPE_DATA_DIR=<scratch> venv/bin/python3 -m pytest tests/e2e -q`. Both green before every commit.
- Tool count after this plan: 79 (was 74). Every doc that says "74" is updated in Task 18.
- Default behaviour of existing tools is unchanged unless the spec says so (the realistic hover default is the one deliberate change).

## Review Focus

1. A click whose only effect is a network request with no DOM change must still report `changed: true` (via `change: ["network"]`), not a false "no page change" hint — pinned in Task 2 (`test_click_network_only_change_counts`).
2. `strategy="auto"` must never re-click after an attempt that *did* change the page (double submit) — pinned in Task 2 (`test_auto_strategy_stops_after_first_change`).
3. `clear_site_data` must never delete cookies (it would log a project session out) — pinned in Task 4 (`test_clear_site_data_keeps_cookies`).
4. `handle_consent` on a page with no banner is a success with `found: false`, not an error — pinned in Task 8.
5. `compare_pages` where one URL fails to load returns the other side's capture plus the error, never a crash — pinned in Task 15.
